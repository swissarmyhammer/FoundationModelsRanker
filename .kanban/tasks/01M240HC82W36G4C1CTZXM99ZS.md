## What

Measured in FoundationModelsMultitool (card ^zqz1zan, 2026-09-09) on `mlx-community/Qwen3-4B-4bit`: the under-budget path, one grammar-constrained call per query, a 9-entry tool catalog (files read/write/edit/patch/glob/grep, shell execute/getLines/grepHistory), the intent under `# Task`.

| preamble | queries answered, of 10 | note |
|---|---|---|
| `.selectionDefault` | 2 | eight `{"ids":[]}`; every query for a way to write, edit or run a command came back empty |
| `.librarianDefault` (registry) | 10 | over-selects: 9 of 9 ids for "run pytest tests, execute" and for "file operations: create, write, append, delete, move" |
| consumer preamble (below) | 10 | `shell.execute` alone for "run pytest tests, execute"; `files.write`, `files.edit`, `files.read` for "write file, edit file, create file" |

The consumer preamble: "The candidates below are the functions a program can call, each under its id. Given a task, answer with the ids of the candidates the program calls to do that task — the fewest that suffice, in call order when order matters. Prefer the closest candidates over an empty answer; answer with an empty list only when no candidate is related to the task at all."

The grammar, the prompt and the blocks were the same in all runs. The consumer now passes this text as `SelectionConfig(model:preamble:)`. That is the seam the config offers, but the default is what every other consumer gets, and on a small model the default answers nothing.

Note: the Ranker card "One demo query returns no match on a cold selection session" measured a V2 wording ("return an empty list only when no candidate is related to the task") on the system model and found that it did not fix that cold-session defect. This card is a different measurement: a 4B MLX model, a warm cached root, and a wording that also says what the candidates are and what an answer is.
