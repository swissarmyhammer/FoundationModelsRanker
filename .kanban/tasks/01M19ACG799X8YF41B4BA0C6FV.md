## What

This repository selects its real-model test with an environment variable, `FOUNDATIONMODELSRANKER_INTEGRATION_TESTS`, checked from inside the unit test target. The shared org workflow calls that mechanism LEGACY in as many words. `FoundationModelsMetadataRegistry/.github/workflows/ci.yml:10-12`:

> No environment variable selects a suite. This workflow gives the shared workflow no `integration-gate-env` (a LEGACY input, kept only for callers that have not migrated).

We are a caller that has not migrated. Every sibling with real-model tests uses a nested package instead — `FoundationModelsACP`, `FoundationModelsACPClient`, `FoundationModelsCodeContext`, `FoundationModelsMultitool`, `FoundationModelsRouter` all pass `integration-package-path: IntegrationTests`.

`FoundationModelsRouter/IntegrationTests/Package.swift` states why the nested package is the better mechanism:

> Selection is structural: this target exists only in this package, so a root `swift test` cannot see it.

Structural selection is what makes the env gate unnecessary. It also removes a real defect this repository has today.

## The defect the migration removes

`Tests/FoundationModelsRankerTests/ExamplesSmokeTests.swift:169-177` — the test "The gate is off when the opt-in environment variable is absent" reads AMBIENT process state:

```swift
try #require(ProcessInfo.processInfo.environment[foundationModelsRankerIntegrationEnvVar] == nil, ...)
```

So `FOUNDATIONMODELSRANKER_INTEGRATION_TESTS=1 swift test` can never be green:

```
✘ Expectation failed: environment[FOUNDATIONMODELSRANKER_INTEGRATION_TESTS] == nil
✘ Test run with 273 tests in 21 suites failed after 1.461 seconds with 1 issue.
```

Do not patch that assertion. The gate it guards is what is going away.
