## What

`Searcher(items)` with the on-device system model answers three of `FullMontyCore`'s four demo queries from a session that has answered nothing yet. It answers the fourth with an empty id list.

Measured while implementing `^w82skg5`. Each probe built its own new `Searcher` over `toolCatalog` and asked one question:

```
PROBE search file contents for a pattern using a regular expression -> ["grep"]
PROBE record my staged changes as a new commit                      -> []
PROBE how do I list or delete a branch                              -> ["branch"]
PROBE temporarily set aside my uncommitted changes to switch tasks  -> ["stash"]
```

The empty answer repeated on three runs out of three, so it is not noise. No `.unknownSelectedId` was reported, which means the tier resolved the answer correctly: the model itself returned `{"ids":[]}`.

The same query answers `commit` inside `runDefaultDemo`. The under-budget selection path caches one root session and reuses it for every query (`SelectionTier`), so `FullMonty`'s second query reaches a session that has already answered the first. One earlier answer is enough to make the model answer this one. A caller who asks one question gets the cold session, and gets nothing.

## Why it matters

`try await Searcher(items)` then one `search(_:limit:)` call is the README's lead example and the package's front door. A caller who asks one question is the common case, not the rare one. "No match" is also indistinguishable from "nothing in the catalog fits", so a caller has no way to tell the two apart.

## Where to look

- `Sources/FoundationModelsRanker/Selection/SelectionTier.swift` — the cached root session, the assembled prefix, and `assemblePrefix(preamble:ids:catalog:)`.
- `Sources/FoundationModelsRanker/Selection/Selection.swift` — the preamble `.selectionDefault`, the guidance the model reads before the ids.
- `IntegrationTests/Tests/FoundationModelsRankerIntegrationTests/ZeroConfigSearcherRealModelTests.swift` — the cold-session test, and the fixture doc comment that records this finding.

## Outcome

Two queries failed cold, not one. The cause was the prompt, not the preamble: `SelectionTier.prompt(prefix:intent:)` framed the intent under a `# Task` heading for a `.session` source and sent the bare intent for a `.factory` source, which is the source the zero-config `Searcher` uses. Both sources now frame the intent. `SelectionConfig.preamble` and `.selectionDefault` are unchanged.
